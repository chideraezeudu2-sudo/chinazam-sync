Getting every credential this app needs

Supabase and Render are already done — this is only about getting real credentials from WooCommerce, eBay, and Amazon, then entering them at chinazam-sync.onrender.com/settings.

✓ Already live: Supabase tables (Fff project) and the Render deployment. Nothing below touches those.

1. WooCommerce (chinazamautoparts.ca)

This gets you the Consumer Key and Consumer Secret the app uses to read your inventory.

1
Log into wp-admin for chinazamautoparts.ca.
2
Go to WooCommerce → Settings → Advanced → REST API.
3
Click Add Key. Description: "Chinazam Sync". User: your admin account. Permissions: Read/Write (Write is required so stock levels can update after a sale).
4
Click Generate API Key. Copy the Consumer Key and Consumer Secret shown — this is the only time the secret is displayed.
5
In the app's Settings page, WooCommerce tab: Store URL is https://chinazamautoparts.ca, then paste the key and secret.

Official doc: woocommerce.com/document/woocommerce-rest-api

2. eBay

eBay needs five things: Client ID, Client Secret, a Refresh Token, your Marketplace ID, and a Merchant Location Key. The refresh token step is the fiddly one — it's a one-time browser sign-in, not just copying a key.

2a. Create a developer account and app keys

1
Join the eBay Developer Program at developer.ebay.com (free).
2
Go to Your Account → Application Keys and create a Production keyset.
3
Copy the App ID (Client ID) and Cert ID (Client Secret).

2b. Set up a redirect (RuName)

1
On the same Application Keys page, find User Tokens and configure an eBay Redirect URL (RuName) — a name for your app, no real server needed since you'll copy a code manually.

2c. Get your refresh token (one-time)

1
Build this URL, filling in your own Client ID and RuName, and open it in a browser:
https://auth.ebay.com/oauth2/authorize?
client_id=YOUR_CLIENT_ID&
response_type=code&
redirect_uri=YOUR_RUNAME&
scope=https://api.ebay.com/oauth/api_scope/sell.inventory
      https://api.ebay.com/oauth/api_scope/sell.fulfillment
2
Sign in with your eBay seller account and click Agree. You'll be redirected to a URL containing ?code=... — copy that code (it's URL-encoded and expires in 5 minutes).
3
Exchange it for tokens — run this from any terminal (or ask me to run it for you if you paste the code here):
curl -X POST https://api.ebay.com/identity/v1/oauth2/token \
  -H "Authorization: Basic BASE64(client_id:client_secret)" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=authorization_code&code=THE_CODE&redirect_uri=YOUR_RUNAME"
4
The response includes a refresh_token — this is long-lived (about 18 months). Save it.

2d. Marketplace ID and location

Marketplace ID for a Canadian store is EBAY_CA. For the Merchant Location Key: in Seller Hub go to Shipping → Locations, create a location for your shop, and copy its key.

Full reference: developer.ebay.com — Quick OAuth Guide

3. Amazon Seller Central (SP-API)

This is the slowest one — the technical setup takes 15–20 minutes, but auto-parts category approval (separate from this) can take days. Start both in parallel.

3a. Register as a developer

1
In Seller Central: Apps & Services → Develop Apps. Complete the developer profile if prompted (one-time).

3b. Create your app

1
Click Add new app client. Name it "Chinazam Sync". API type: SP-API, environment Production.
2
Under roles, select at minimum: Inventory and Order Tracking and Product Listing.
3
Save, then open LWA Credentials to copy your Client ID and Client Secret. (Amazon expires this secret every 6 months — you'll need to regenerate and re-enter it then.)

3c. Self-authorize (get your refresh token)

1
Back in Develop Apps, open your app's menu and choose Authorize.
2
Click Authorize app for your Canada marketplace. A Refresh Token appears — copy it immediately, it's shown once.

3d. IDs you'll also need

Seller ID: Settings → Account Info → Business Information → "Your Merchant Token". Marketplace ID for Amazon.ca is A2EUQ1WTGCTBG2. Region is na.

3e. Category approval (do this in parallel)

Many auto-parts subcategories are gated. In Seller Central, search Add a Product for an auto part and look for an "Apply to sell" prompt — this approval is separate from the API access above and is usually the longer wait.

Official guide: developer-docs.amazon.com — Self Authorization

4. Using the app once credentials are in

  1. Go to /settings and fill in each tab. Each save is independent — you can do WooCommerce today and eBay next week.
  2. Go to the dashboard and click Pull from WooCommerce first, always — it's the source of truth.
  3. Then Push to eBay and/or Push to Amazon.
  4. Run Reconcile stock from orders periodically (or whenever you suspect a sale happened) so stock stays accurate across all three places.

5. If something fails

Every run is logged under "Recent activity" on the dashboard with the actual error message — that's the first place to look. Common ones:

  • WooCommerce 401: the key was created with Read-only permission — recreate it as Read/Write.
  • eBay "invalid_grant": the refresh token expired (~18 months) or was typed with extra whitespace — regenerate via section 2c.
  • Amazon "Unauthorized": the LWA client secret rotated (Amazon does this every 6 months) — grab the new one from LWA Credentials.
  • Amazon listing errors mentioning "gated": that category needs the approval from step 3e before it'll accept listings.
